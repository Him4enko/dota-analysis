# Кодбук ручной разметки

Задача разметчика: для каждого документа решить, является ли он **жалобой на систему
порядочности/вежливости Dota 2**.

## Что считается жалобой (`label = 1`)

Сообщение, в котором автор **выражает недовольство** системой поведения или её элементом:

- Behavior Score / Conduct Summary: несправедливо снизился, не растёт, «сломан», обнулился,
  нет объяснений, система несправедлива;
- Communication Score / коммендации: несправедливая оценка общения, «коммуникационный бан»;
- репорты: ложные репорты, наказание за репорты, «кинули репорт», абьюз системы репортов;
- Low Priority: несправедливый LP, слишком долгий LP, LP за чужие действия;
- Overwatch: неверный вердикт, отсутствие апелляции, «система банит невиновных»;
- мьюты/баны за поведение: несправедливый бан, бан без причины, «забанили за слово»;
- общая несправедливость системы наказаний, отсутствие прозрачности/апелляции.

Жалоба может быть в форме вопроса («почему меня забанили за репорт?»), если в тексте есть
негативная оценка или описание несправедливости.

## Что НЕ считается жалобой (`label = 0`)

- нейтральные вопросы без недовольства («как работает behavior score?», «сколько максимум?»);
- гайды и советы («как поднять BS», «играйте без чата»);
- новости/патчноуты без оценки;
- одобрение системы («заслуженно забанили», «система работает»);
- жалобы на игроков/токсичность **без** упоминания системы поведения;
- оффтоп (баги героев, предметы, баланс, баттлпасс);
- сарказм, восхваляющий систему (например, «конечно, система идеальна» — если нет явного
  недовольства, ставим 0 и отмечаем в `notes`).

## Порядок

1. Открыть `data/validation/sample_to_label.csv`.
2. Заполнить колонку `label` (1/0). Колонку `notes` — по желанию (причины спорных решений).
3. Сохранить как `data/validation/labels.csv`.
4. Запустить `python scripts/analyze_all.py` — метрики валидации попадут в отчёт.

Разметка выполняется по заголовку и первым ~420 символам текста; если контекста недостаточно,
ориентируйтесь на явные маркеры недовольства, а не на догадки.

## Известные ограничения разметки

- Разметка выполнена **одним аннотатором** (исследовательский ассистент) по данному кодбуку;
  межаннотаторная надёжность (IRR) не измерялась. Это ограничивает интерпретацию каппы:
  она показывает согласие «правила ↔ разметчик», а не «разметчик ↔ разметчик».
- Текущая проверочная выборка — 120 документов, распределённых пропорционально между
  источниками и случайно выбранных внутри каждого источника. Такой дизайн позволяет
  постстратифицировать общую долю по известному размеру источников в корпусе.
- Доля оценивается только внутри автоматически найденного релевантного корпуса; проверка
  не измеряет пропуски релевантных сообщений на этапе поиска/фильтрации.
- Спорные случаи (сарказм, защита системы, технические баги) решались в пользу строгого
  определения жалобы; такие метки снижают чувствительность классификатора.
